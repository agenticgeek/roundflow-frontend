Source plan: `docs/GAP_ANALYSIS_AND_REMEDIATION_PLAN_2026-11-06.md` (ACT-01, ACT-02 to ACT-04, ACT-10, GHL-10,

## What changed

### ACT-01: Invoices page, status filter and "Send all"

- The status filter (a labelled select) now offers Draft, Sent, Paid, Void and **Overdue** (`GET /invoices?status=OVERDUE`).
  No per-status counts: there is no endpoint for them.
- Draft rows have a checkbox (24px target, `aria-label` "Select invoice INV-001"); the header has a labelled
  select-all checkbox with an `indeterminate` state. Read-only users see neither.
- With the filter on Draft the page shows **Send all (N)** (N = drafts matching the current search and dates). With rows
  ticked it shows **Send selected (N)**.
- `components/invoices/BulkSendInvoicesModal.tsx`: step 1 calls `POST /invoices/bulk-send/preview` and lists the
  count that will send, counts by channel and skip reasons in plain language (and a note when the server truncates at 500).
  A channel picker re-checks the preview. Step 2 `POST /invoices/bulk-send` (202), then polls
  `GET /invoices/bulk-send/:batchId` every 2 s until `done`. A `role="status"` line announces progress then
  "Finished: 12 sent, 2 failed, 1 skipped.". Failures are listed with the server's error; **Retry failed** re-sends
  just those ids. The button disables while the request is pending (and the server treats a repeat as `ALREADY_QUEUED`).
- Errors: `GHL_NOT_CONNECTED` ("Messaging is not connected" + link to Settings > Integrations),
  `EMAIL_NOT_AVAILABLE` (also added to `MESSAGING_ERROR_CODES`, so the single-invoice send explains it too),
  `INVALID_BATCH_SIZE`, anything else a generic line.
- Files: `api/invoice-bulk-send.api.ts`, `features/invoices/hooks/useBulkSend.ts`, `features/invoices/lib/bulk-send.ts`,
  copy in `content/invoices.ts` (`bulkSend`).
- The poll query key starts with `bulk-send`, not `invoices`: the hook refreshes the invoice list when the batch is done,
  and a key under `invoices` would be invalidated by its own refresh and loop.

### ACT-02 to ACT-04: carryover in Close Operational Day

- `CloseOperationalDayModal` takes a new `date` prop (the day being closed). Choosing "Push to tomorrow" fetches
  `GET /visits/carryover/options?date=`. `CarryoverChoice` shows a **radio group** (Saturday / Monday, Monday preselected,
  dates shown) whenever the server returns two options (every Friday), otherwise one plain sentence. Sunday is never offered
  because the server never returns it.
- "Also tell affected customers" is an unticked checkbox with help text.
- The confirm step shows `CarryoverPreview`: a **dry run** (`POST /visits/carryover { dryRun: true }`): jobs that will move,
  technician conflicts by **name** (resolved from the technicians list) and reason, a link to the Round Planner to reassign,
  and how many jobs stay put. A failed preview does not block closing.
- Confirm sends `POST /today/close { unfinishedAction: 'push_to_tomorrow', target }`. When the customer box is ticked the
  modal first calls `POST /visits/carryover { notifyCustomers: true }` (the only endpoint that messages customers), then closes.
- After success the modal stays open on a `role="status"` result: jobs carried over and the date (`carriedToDate`), and,
  when customers were told, how many and any `customerNotificationError`. 400s from close show the server's reason inline
  (`INVALID_CARRYOVER_TARGET` etc. have friendly copy in `content/carryover.ts`); this replaces a silent return.
- A **"Carried over from <date>"** badge shows on visit cards in Today's Work (`carriedOver` / `carriedOverFromDate`).
- Not done: `PushMissedJobsModal` (`POST /rounds/:id/push-missed`) is a different endpoint that is not in the Wave 2A contract; it is unchanged.
  The rounds table does not show the new `carriedOver` count.

### ACT-10 / WEB-10 / WEB-19: maps

- One shared canvas, `components/maps/StopsMapCanvas.tsx`, now serves the Round Planner map and the dashboard GPS panel
  (the GPS panel's copy-pasted canvas is gone).
- **Grouping instead of a clustering library.** `@googlemaps/markerclusterer` is not a dependency and adding one was not
  authorised, so stops whose coordinates agree to 4 decimals (about 11 m) share one pin: a rounded square showing the count,
  coloured by the most urgent status, opening one info window that lists every stop. This fixes the real problem (a postcode
  centre stacks every property in the postcode on one point); it does not cluster merely nearby pins at low zoom. Swapping in
  the library later only changes `StopsMapCanvas`.
- `fitBounds` zoom is capped at 17 (`MAX_FIT_ZOOM`, `fitBoundsCapped`).
- `AdvancedMarkerElement` when `google.maps.marker` loaded, otherwise the legacy `Marker` (`features/maps/lib/gmaps.ts`).
  The map takes `mapId` from **`VITE_GOOGLE_MAPS_MAP_ID`**, default Google's `DEMO_MAP_ID` (documented in `.env.example` and
  `vite-env.d.ts`). Create a real map ID in the Cloud Console before production.
- **The Geocoding library is no longer loaded.** Verified unused (`Geocoder` is not referenced anywhere); `lib/google-maps.ts`
  now imports `maps` and `marker`. The browser key therefore no longer needs the Geocoding API.
- Info window: address, customer, price, round, technician (or "Unassigned"), visit date (week view only, from the new
  `date` on gathered stops), status as text, navigate link, and an "Approximate location" note. All values are escaped.
- Accessibility: the map is `role="region"` named "Map of stops. The list of stops next to the map has the same
  information."; a visible note over the list says the same; pins carry a title and a letter or count (check, pound, !)
  so status is not colour-only; stops without a pin say "Location not found" in the list.
- "No stops match these filters" overlay (`role="status"`) when the filtered set is empty.
- `locationApproximate`: "Approximate location" badge on list rows, pins' info windows and the property page
  (`components/maps/LocationNote.tsx`). `latitude: null` shows "Location not found".
- A saved property (create or update) whose response has `latitude: null` toasts "Saved, but there is no map location yet"
  (`features/maps/hooks/useLocationWarning.ts`, called from `useCreateProperty` / `useUpdateProperty`).

### GHL-10: invoice footer and payment terms

Settings > Payment Setup has two optional fields, **Invoice footer** (max 500) and **Payment terms** (max 200), with help
text, length errors tied to the field with `aria-describedby` and `role="alert"`, saved through `PATCH /settings/payment`;
a blank field is sent as `null` (clears it). Logic in `features/settings/lib/invoice-details.ts`.

### Deep links

- `?visitId=` `?round=` `?date=` (validated by `lib/deep-link.ts`; malformed values are dropped). `useDeepLink()` reads them once.
- **Round Planner**: opens the List view on that round and day with the visit expanded; the row is scrolled to,
  focused (`tabIndex=-1`) and marked `aria-current` (`useHighlightFocus`).
- **Today's Work**: `?round=` opens that round's panel, `?visitId=` focuses that visit card. Today's Work only ever shows
  today, so a link for another day shows a notice with a link to the Round Planner for that day. A bare `?visitId=` cannot
  find its round (the aggregate has no stops), so links should carry `round`.
- `NotificationCentre` links (`notification-link.ts`): SCHEDULE / ROUND_UPDATE with a round open the planner on round, day and
  visit; ACCESS_ISSUE with a visit **and** round opens Today's Work on the visit (without a round it still goes to the property
  page); DAY_CLOSED opens Today's Work (with `?date=` when sent). Other types are unchanged except the generic visit/round links
  now carry the parameters.

### WEB-13 leftover: mobile navigation drawer

`AppMobileNav` uses `useDialogA11y`: `role="dialog"`, `aria-modal`, named "Main menu", focus trap, Escape, inert page, focus
returns to the menu button. The backdrop close button is `tabIndex=-1`.

### WEB-20 note

New controls use 24px+ targets (`h-6 w-6` checkboxes and radios, `min-h-6` buttons). Existing sub-24px controls elsewhere
were not part of this wave.

### How to regenerate `types.gen.ts`

With the backend running locally with the Wave 2A build, run the generator from the Wave 1 contract
(`roundflow-backend/docs/handoff/frontend/2026-11-06-wave1-frontend-contract.md`; it fetches `/openapi.json` into
`src/api/types.gen.ts`). Then `npx tsc -b`: MSW handlers built with `on()` / `specJson()` fail to compile where a body drifts.
Delete the matching hand-typed shapes above, replacing them with `components['schemas'][...]`.

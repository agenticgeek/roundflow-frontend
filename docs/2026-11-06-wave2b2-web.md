## Regenerating types

```
npx openapi-typescript "<path to openapi.json>" -o src/api/types.gen.ts
npx tsc -b
```
or `npm run generate:types` against a dev backend (production closes `/openapi.json`). Run `npx tsc -b` after: typed MSW handlers (`on()` / `specJson()`) fail where a body drifts.

## Screens

- **Settings > Email and branding** (`features/email/`, `content/email-settings.ts`, route `/settings/email`). Visible to ADMIN and MANAGER; a MANAGER sees everything read-only with the reason (`AdminOnlyNote`, `aria-describedby` on the read-only fields).
  - Status: on / off / not set up / paused, sent today of the daily limit, delivery health (last N emails). A paused account shows a `role="alert"` banner with the cause (`pausedReason`) and, for an ADMIN, **Resume email** (`PATCH { emailPaused: false }`).
  - Sender name, reply-to, enabled switch, sender preview ("Customers see emails from"), one Save that sends only changed fields (cleared fields as `null`).
  - **Brand colour** (`BrandColourField`): text input plus colour picker, live WCAG contrast preview computed client side (`lib/colour.ts`), shows button text colour, contrast ratio and a warning; once the saved colour matches the one being edited the backend's `brandColourCheck`/`warning` (message and `safeAccentColour`) wins. Invalid hex is flagged in words.
  - **Logo** (`LogoField`): upload-url, PUT of the bytes to the signed URL, `PUT /settings/email/logo { path, altText }`; remove; preview `alt` = saved description, else the business name; alt text required before upload; PNG/JPEG/WebP only.
  - **Send a test email to me** (`POST /settings/email/test`), result or the `CHANNEL_UNAVAILABLE` reason.
  - **Domain verification** (`DomainVerificationPanel`): tier 1 (shared sender) vs tier 2 (own domain) explained; start verification (domain, optional sending name); the three DKIM CNAME records in a table with copy buttons that name the record ("Copy value of record 2") and announce the result; status chip as words plus a symbol; Check now, automatic re-check every 30 s while PENDING; remove with confirm. `FREE_MAIL_DOMAIN` and the other domain codes have plain explanations.
- **Settings > SMS and calling (optional)** replaces "Integrations": copy says email is sent by RoundFlow and GoHighLevel is only for SMS and WhatsApp. The setup wizard code has no GoHighLevel gate (checked by search), so setup completes without it; its footer copy now says so.
- **Phone links:** the property page contact card always shows `tel:` links for mobile and landline (`lib/tel.ts`).

## Channel-aware messaging

- `useChannels()` reads `channels` from the business profile (everything assumed available until it loads); `useChannelChoice()` starts send dialogs on **Email** when it works, else SMS, else Auto.
- `ChannelPicker` (invoice send, bulk invoice send, payment reminder, payment link, property invoice panel, today's bulk invoices) disables unavailable channels and explains why in text tied by `aria-describedby`. The property message modal, the round message composer and the dashboard bulk message modal do the same and default to email (SMS when email is off).
- `409 CHANNEL_UNAVAILABLE` + `reason` maps to plain copy and the right link (`content/shared-actions.ts` `channelReasons`): GHL_NOT_CONNECTED "SMS needs GoHighLevel, which is not connected", EMAIL_NOT_CONFIGURED, EMAIL_TURNED_OFF, EMAIL_PAUSED, EMAIL_DAILY_LIMIT, EMAIL_ADDRESS_INVALID, NO_AVAILABLE_CHANNEL; `CUSTOMER_OPTED_OUT`. Used by every `MessagingErrorNotice`, the bulk-send start error and the email settings test.
- Bulk invoice skip reasons renamed (`CUSTOMER_OPTED_OUT`, `NO_AVAILABLE_CHANNEL`). Broadcast results show `skippedNoChannel` and the `skipped_no_channel` status. Debt bulk reminders that come back `skipped: true` show as "Skipped: ..." in muted text, not as errors.
- Invoice send modal: email preselected, note that the PDF is attached, `pdfAttached: false` gives "sent ... but without the PDF attached", resend unchanged. `POST /invoices` with `sendEmail: true` now reports `emailSent: false` + `emailError` as "Invoice saved as a draft. The email was not sent: <reason>".
- Delivery status chips (`DeliveryStatusChip`: SENT, DELIVERED, BOUNCED, COMPLAINED, FAILED, words plus a symbol, error text beside it) are shown in the complaint message thread.

## Other contract items

- Close day: ONE `POST /today/close` call with `notifyCustomers`; the carryover-then-close workaround and `useCarryover` are gone. The result panel reads `outstanding`, `notifiedCustomers`, `customerNotificationError`.
- Delete customer/property: `409 UNPAID_INVOICES { count, total }` is explained inside the dialog.
- Visit history shows "Collected via <method>" when `collectedVia` is present.
- Debt bucket `FOURTEEN_DAYS_OVER` was already handled.

## Not done

- **Customer "email address bounced" warning:** `emailInvalidAt` exists only on the raw `Customer` schema, not on `CustomerDetail`, `CustomerListRow` or the property DTO the web reads, so there is nothing to show it from. Needs the backend to expose it on those DTOs.
- Message history with delivery chips beyond the complaint thread: no other web screen lists sent messages, and no DTO carries `deliveryStatus` yet.
- The `INTEGRATION` notification "Email sending paused" opens Failed integration messages; it should open Email and branding (the notification has no `data` to tell the two apart).
- Logo upload sends a raw `PUT` of the file to the signed URL; not exercised against real storage.

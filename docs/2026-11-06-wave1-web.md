## What changed

### Session handling (WEB-01, WEB-04)

- `src/api/client.ts`: on a 401 the client refreshes the session and retries **once for every method**,
  re-sending the request body (it used to retry only body-less GETs). If the retry is also rejected it
  calls `handleSessionExpired()`. Provisioning calls (`accessToken` override) and `public` calls are left
  alone.
- `src/lib/session-expiry.ts` (new): `handleSessionExpired()` signs out, remembers the current path and a
  "session expired" flag in `sessionStorage`, and sends the browser to `/login`. It is idempotent and does
  nothing on the sign-in screens (no redirect loop). Also holds `isSafeInternalPath()` (same-origin,
  in-app paths only; rejects `//host`, `/\host`, absolute URLs, control characters and the sign-in
  screens) and `readReturnTo()`.
- `src/lib/query-client.ts`: the global mutation handler no longer swallows 401 or 403. 401 runs
  `handleSessionExpired()`; 403 shows one deduplicated error toast ("You don't have permission to do
  that", with the server reason as description); 400 stays inline in the form that sent it. Screens that
  render their own error can still opt out with `meta: { silenceGlobalError: true }`.
- `src/pages/Login.tsx`: shows a `role="status"` notice "Your session expired. Sign in again to
  continue." once.
- `src/providers/RouteGuards.tsx`: `ProtectedRoute`, `IntegrationsReturnRoute` and `StripeCallbackRoute`
  pass `state={{ from: location }}` to Login; `GuestRoute` (which wraps Login) sends a signed-in user to
  `from` (or the path saved by an expired session) instead of the dashboard. Technicians and unfinished
  setups still go to their own place first.

### Dialogs (WEB-02, WEB-13)

- `src/hooks/use-dialog-a11y.ts` (new) is used by `Modal` and `SidePanel`; see the contract below.
- `src/components/ui/confirm-dialog.tsx` (new) is used for: delete service area, deactivate or delete a
  technician in Settings (now with try/catch, the error shown in the dialog), and delete incident

- `Modal` gained `role` (`dialog` | `alertdialog`) and `descriptionId` props.
- Not done: the mobile navigation drawer (`AppMobileNav`) still lacks dialog semantics; it does not use
  `Modal`.

### Chat (CHAT-01)

- `components/chat/TechnicianChat.tsx`: the dead-end empty state is replaced by "Start a conversation"
  (a round picker plus button). The picker lists the technician's active rounds
  (`features/chat/hooks/useTechnicianRounds.ts`, built on the cached rounds list and round details).
  Choosing one opens `ChatThreadView` for that round even though `GET /chat/threads` has no thread;
  the first send creates it and invalidates the threads query. When some rounds already have a chat, a
  compact "Message another round" picker sits above the thread.
- The technician detail page already had a "Send Message" button that opens the Conversation tab.
- Today's Work round panel: new "Message technician" link to
  `/technicians/:id/conversation?round=<roundId>`; the Conversation tab opens that round first.
- The round planner detail panel only has the technician's name, not an id, so no shortcut was added there.

### Assigning technicians (FLOW-02)

- When `visitsUpdated + visitsGenerated` is 0 the warning reads "No visits exist yet for this round, so

  date, says none are due).

## New shared components and their accessibility contract

### `useDialogA11y` (used by `Modal` and `SidePanel`)

- Focus moves into the dialog on open: `[data-autofocus]`, else the first focusable control, else the
  dialog element itself (`tabIndex={-1}`). A child that already took focus with `autoFocus` keeps it.
- Tab and Shift+Tab wrap inside the dialog. Focus inside something portalled out of it (a dropdown
  menu) is left alone.
- Escape closes only the topmost open dialog (module-level stack).
- Everything else directly under `<body>` gets `inert` while a dialog is open, except elements marked
  `data-toast-viewport` so toasts (Retry buttons) stay usable. `inert` is removed on close.
- Focus returns to the element that opened it, unless it is gone or the user already moved focus.
- The backdrop close button is `tabIndex={-1}` (mouse affordance only; Escape and the close button are
  the keyboard routes).
- Rules for callers: give the dialog a title; keep `onClose` side-effect free apart from closing; do not
  render a second dialog by manipulating `document.body` yourself.

### `ConfirmDialog`

`<ConfirmDialog open title description confirmLabel tone pending error onConfirm onClose />`

- `role="alertdialog"`, named by `title`, described by `description`.
- Initial focus is **Cancel** (the safe choice). Escape and Cancel close it; both are blocked while
  `pending`.
- `tone="danger"` (default) styles the confirm button as destructive.
- `error` renders in a `role="alert"` paragraph and the dialog stays open, so a failed action is never
  silent. The caller owns the action: run it in `onConfirm`, catch errors, then close.
- Never confirm on a bare click of the trigger; open the dialog instead.

### `NotificationCentre`

- Bell button: accessible name includes the unread count ("Notifications, 3 unread" or "none unread"),
  `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`. The visual badge is `aria-hidden`.
- A visually hidden `role="status"` `aria-live="polite"` region announces "N unread notifications" when
  the count goes **up**; nothing on first load or when it goes down.
- The popover is a non-modal `role="dialog"` (no focus trap, no inert page). Focus moves to it on open;
  Escape closes it and returns focus to the bell; a click elsewhere or tabbing out closes it.
- The list is a labelled `<ul>`; each row is a real link (when it has a page) or button, with
  "Unread."/"Read." text for screen readers, a `<time datetime>`, and marks the notification read when
  activated. "Mark all read" is a real button; failures are `role="alert"`.
- Important notifications never auto-dismiss: there are no toasts here.

## Regenerating `types.gen.ts` once the backend handoff exists

The contract note will be `roundflow-backend/docs/handoff/frontend/2026-11-06-wave1-frontend-contract.md`
(it did not exist when this was written). When it does and the backend OpenAPI is updated:

1. `npm run generate:types` (downloads `openapi.json` from `VITE_API_URL`, default the Railway backend,
   and runs `openapi-typescript`; set `VITE_API_URL` to the environment that has the new routes).
2. `npx tsc -b`, then replace each hand-typed block below with the generated type and delete its TODO.
3. Switch the notification test handlers to the typed `on()` / `specJson()` helpers, and add the new
   fields to the default `PUT /rounds/{id}/technicians` handler in `src/test/msw/handlers/rounds.ts`.
4. `npm run test:coverage` and `npm run test:diff-coverage`.
